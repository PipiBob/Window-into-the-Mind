# Study reader and GitHub Pages

The study reader uses Academic Skimming v3 for all three papers when all local source assets are available. The application and annotations run in the browser. Use `npm ci` and `npm run build` for the local production build, then `npm run preview`. Open individual papers with `?paper=programming`, `?paper=anger`, or `?paper=ethereum`.

The Pages artifact is built with `npm run build:pages` and checked by `node scripts/frontend/check-pages.mjs`. It uses relative URLs and a separate staging directory. Papers marked redistribution-cleared in [the pinned catalog](papers.json) are hosted in the build. The two Scientific Reports PDFs carry a CC BY 4.0 notice. The PDFs are preserved byte-for-byte and guided by separate overlays. PDF.js redistribution notices accompany the vendored files.

The Ethereum PDF is fetched directly from arXiv rather than copied to GitHub Pages. Pages includes a reference-only sidecar for the existing passage locations, labels and coordinates. The reader verifies the exact PDF digest, then restores the passage text from the authorized PDF. Ethereum depends on arXiv remaining reachable. The arXiv license applies to arXiv's distribution. [arXiv record](https://arxiv.org/abs/2502.05054) · [Submission license](https://arxiv.org/licenses/nonexclusive-distrib/1.0/)

The Pages workflow is manual so that pushing the integration does not publish a new release automatically. To deploy an approved release, select GitHub Actions as the Pages source and run the workflow from a repository branch with the workflow available on the default branch. Use the Pages environment URL after successful deployment. [GitHub Pages workflow setup](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
